ETA is a constant-speed active-leg prediction from a fresh feed position, routed sea distance or great-circle air distance. The displayed range is sensitivity to ±20% speed, not a statistical percentile. Confidence is limited and uncalibrated. Port-call arrival-versus-reported-ETA history is available only where Digitraffic supplies Finnish calls; it is not a worldwide congestion index or measured anchorage waiting time. Missing historical data is explicit.

Old exception scanner is restricted to its own rule prefixes so it cannot silently clear visibility alerts.

Milestones do not advance from the clock. DCSA events must include ACT to establish movement, EST updates ETA, PLN is only retained as evidence. A gate-out event is not treated as delivery dispatch. Feed ingestion is deduplicated by provider, shipment, leg and event ID. Tests use synthetic edge cases, separately labeled from real provider probes.

## Public observation refresh (r8 continuation)

`visibility.public` runs every 60 seconds through core.jobs, independently of customer/demo shipments and with Autopilot OFF. It ingests up to 500 fresh vessel positions from the official [Digitraffic AIS API](https://www.digitraffic.fi/en/marine-traffic/) and up to 500 fresh aircraft positions within 250 nautical miles of Helsinki from the [adsb.lol point API](https://api.adsb.lol/docs). The Finnish-waterways AIS overview is regional; this does not satisfy worldwide AIS coverage. Shipment-specific flight callsign lookup retains the provider's worldwide receiver coverage. Missing coverage is never manufactured. No provider key or new config is required for public observations; existing DIGITRAFFIC_ENABLED applies to AIS.

API projections `/api/visibility/vessels` and `/flights` return the newest observations first and exclude future/stale data. Provider timestamps survive unchanged. Stationary AIS/ADS-B/GPS fixes update shipment persistence and SSE timestamps. AIS older than 15 minutes cannot establish a fresh position or milestone. Area and callsign flight writes are monotonic. The existing map distinguishes these observations from cargo movement.

The new job is monitoring, not an agent action; it creates no shipments, customers, KYC approvals or carrier requests. Failures are exposed by `/status` per provider. `digitraffic` reports Finnish-waterways coverage; `adsb.lol.area` reports the Helsinki radius. These local implementation checks do not establish deployed capability status.
